# البنية والقرارات التقنية — ذاكرة المحادثة

هذا الملف لأي مطوّر يراجع الشيفرة: ما كل جزء، ولماذا بُني هكذا. كل قرار مكتوب بسببه والبديل الذي رُفض.

## الصورة العامة

```
                 ┌───────────────────────────┐          ┌───────────────────────────┐
                 │  بلقن Claude Code          │          │  إضافة المتصفح             │
                 │  plugin/scripts/           │          │  extension/src/            │
                 │  يقرأ سجل الجلسة، يطلب     │          │  يقرأ صفحة المحادثة، يطلب   │
                 │  مسودة من Claude           │          │  ملخصاً داخل المحادثة       │
                 └─────────────┬─────────────┘          └─────────────┬─────────────┘
                               │  مسودة JSON                          │  رد JSON
                               ▼                                      ▼
                 ┌──────────────────────────────────────────────────────────────────┐
                 │  core/memory-core.js — المكتبة المشتركة (نسخة واحدة حرفياً)       │
                 │  تتحقق من المسودة، تحذف الحساس، تطبّق العمليات، تولّد العرض      │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                │  بعد أخذ القفل المشترك
                                                ▼
                 البلقن: مجلد المشروع · الإضافة: داخل المتصفح لكل مشروع في الموقع (أو مجلد تربطه)
                 CONVERSATION_MEMORY.json (المرجع) · .md (عرض) · CONVERSATION_PINS/ · .conversation-memory/
```

## خريطة الوحدات

### البلقن (`plugin/scripts/`)

| الملف | المسؤولية الوحيدة |
|---|---|
| `hook.js` | نقطة الدخول: يحدد الحدث، يأخذ قفل العملية، يوزّع على المعالج |
| `lib/config.js` | كل الحدود والإعدادات في مكان واحد |
| `lib/util.js` | دوال صغيرة نقية (تواريخ، بصمات، أرقام) |
| `lib/fsx.js` | عمليات الملفات الآمنة: رفض الروابط، كتابة ذرية، تحقق بالقراءة |
| `lib/context.js` | مدخلات الاستدعاء ومسارات كل الملفات |
| `lib/state.js` | الحالة الخاصة (العدّاد والدفعات) وقفل العملية وملف المؤشر |
| `lib/transcript.js` | قراءة سجل الجلسة، ونسخ الرسائل غير الملخّصة كاملة |
| `lib/requests.js` | ما المستحق وما يُطلب من Claude، والأوامر |
| `lib/store.js` | الكاتب الوحيد لملفات الذاكرة والنصوص المثبّتة |
| `lib/handlers.js` | معالج لكل حدث (رسالة، نهاية رد، بداية جلسة، أداة) |
| `lib/features.js` | أدوات المستخدم على الذاكرة: التصحيح، وسجل النصوص المعتمدة، والنقل إلى محادثة أخرى |
| `hooks/indicator.ts` | المؤشر في شريط الحالة؛ يقرأ ملف الحالة فقط |

## القرارات

**1. ملف JSON هو المرجع، وملف Markdown عرض يُولَّد منه.**
البديل المرفوض: Markdown بعلامات داخلية (كما في 0.x). السبب: النص الحر هش كقاعدة بيانات، وأي تعديل يدوي يكسر الحفظ. ويبقى Markdown للقراءة، وتعديله اليدوي يُحفظ في نسخة جانبية قبل إعادة التوليد.

**2. المسودة عمليات (أضف قراراً، ألغِ قراراً، أضف سجلاً)، لا استبدال للملف كله.**
السبب: كاتبان (البلقن والإضافة) لا يمحو أحدهما عمل الآخر. واستبدال الخلاصة وحده يحتاج أن تكون مبنية على النسخة الحالية (`base`).

**3. النموذج لا يكتب ملفات الذاكرة أبداً.**
يكتب مسودة فقط، والسكربت يتحقق منها ثم يكتب. السبب: لا يُسجَّل نجاح إلا بعد قراءة الملف المكتوب، ولا يدخل الملف شيء لم يمر بالتحقق.

**4. مكتبة واحدة منسوخة حرفياً في الحزمتين، بلا خطوة بناء.**
البديل المرفوض: حزمة npm مشتركة أو أداة تجميع. السبب: كل حزمة تبقى مستقلة وتعمل كما هي، واختبار يفشل إن اختلفت النسختان بحرف (`npm run check-core`).

**5. حالة البلقن الخاصة خارج المشروع** (`~/.conversation-memory/projects/<بصمة المسار>/`).
البديل المرفوض: توقيع الحالة بمفتاح (كما في 0.3). السبب: مشروع منسوخ أو مستودع مشترك لا يستطيع زرع حالة أو رسائل مزيفة، وبلا تعقيد المفاتيح.

**6. ثلاث طبقات ضد الكتابة المتزامنة.**
قفل عملية للبلقن (جلستان في نفس المشروع)، وقفل كتابة مشترك مع الإضافة في `.conversation-memory/write.lock` عند ربطها بمجلد، وإعادة قراءة الملف قبل استبداله مباشرة (بعد النسخة الاحتياطية) وبعده. ومن لا يحصل على القفل لا يكتب شيئاً. وداخل المتصفح لا يلزم القفل: الإضافة تنفّذ طلباً واحداً في كل لحظة (`navigator.locks`)، ولا يصل إلى تخزينها برنامج آخر.

**7. كل كتابة ذرية ومتحقَّق منها.**
تُكتب إلى ملف مؤقت ثم يُستبدل الأصل دفعة واحدة، ثم يُقرأ للتأكد. فالإغلاق المفاجئ يترك النسخة القديمة كاملة أو الجديدة كاملة. وقبل كل استبدال نسخة احتياطية.

**8. الرسائل غير الملخّصة تُنسخ كاملة قبل ضغط السياق وعند الإغلاق**، مطابقةً بمعرّف الرسالة الأصلي. السبب: فشل التلخيص لا يضيّع نصاً.

**9. لا تحميل للذاكرة عند استئناف نفس الجلسة، وتحميل مختصر (حتى 5,000 حرف) في الجلسة الجديدة.** السبب: الاستهلاك.

**10. أوامر صريحة** (`/conversation-memory:save` وأخواتها)، ولا تُحتسب ضمن الرسائل. ومعها عبارتان عربيتان بنصهما الكامل فقط: «احفظ الذاكرة» و«حالة الذاكرة» (الرسالة كلها، لا جزء منها). البديل المرفوض: فهم الكلمات («احفظ الآن»، «ثبّت هذا»)، لأنه يخطئ.

**11. الإضافة تكتب عبر مستند خفي، بلا خادم.** السبب: لا تخرج بيانات المستخدم من جهازه إلا ما يكتبه هو في المحادثة.

**12. الإضافة تطلب الملخص داخل المحادثة نفسها.**
البديل المرفوض: استدعاء نموذج عبر API بمفتاح. السبب: لا مفاتيح ولا كلفة إضافية على المستخدم. والمقايضة معلنة: الطلب ورده يظهران في المحادثة ويأخذان من سياقها.

**13. الربط بالمشروع بإثبات، ومعرّف المشروع داخل مجلده.**
المحادثة تنضم تلقائياً فقط إن أُرسلت أول رسالة فيها من صفحة محادثة جديدة في نفس التبويب. وتغيير المجلد لا ينقل أي محادثة.

**14. بصمة لكل رسالة، وأخرى لها مع ردودها**، لاكتشاف التعديل وإعادة التوليد، بشرط الثبات في فحصين وحد 3 مرات في نصف الساعة.

**15. لا تقنيات جديدة ولا تبعيات وقت التشغيل.**
JavaScript عادي في البلقن والإضافة. والمؤشر بـ TypeScript لأن Claude Code يتطلب ذلك لوحدات الواجهة. وأدوات التطوير (الاختبار والفحص) خارج الحزم المنشورة.

**16. النسخ الاحتياطية في مجلد المشروع** (`.conversation-memory/backups/`، آخر 20، مستثناة من git)، مشتركة بين البلقن والإضافة.
السبب: «التراجع» يعيد آخر تغيير أياً كان كاتبه. ولا تُستبدل نسخة دون نسختها الاحتياطية: إن تعذّر حفظ النسخة الاحتياطية لا يُكتب شيء. والاسترجاع نفسه يحفظ الحالية أولاً، فيمكن التراجع عنه.

**17. فشل الكتابة لا يضيّع المسودة.** إن رفض نظام الملفات الكتابة (صلاحيات، قرص ممتلئ، نسخة احتياطية متعذرة) تبقى المسودة وتُعاد المحاولة بعد الرد التالي، ولا تُحتسب محاولة فاشلة، ولا يُطلب من Claude إعادتها.

**18. استعادة ما بعد الانهيار.** جلسة انتهت دون حدث الإغلاق (انهيار، طرفية أُغلقت بالقوة) تُنسخ رسائلها غير الملخّصة عند بداية الجلسة التالية، إذا لم تتحرك هي ولا سجلها منذ نصف ساعة (فالجلسة الخاملة المفتوحة تلخّص رسائلها بنفسها). وقفل الكتابة الذي تركه برنامج مات على نفس الجهاز يُعدّ منتهياً فوراً، لا بعد 15 ثانية.

**19. العرض المولَّد ليس تعديلاً يدوياً.** إن قُطعت الكتابة بين الملفين بقي ملف Markdown عرضاً لنسخة سابقة. يُعرف ذلك بمطابقته لأي نسخة محفوظة، فيُعاد توليده بلا إنذار كاذب. ولا يُحفظ جانباً إلا التعديل اليدوي الحقيقي.

**20. التصحيح عملية محددة، لا تحرير حر للملف.**
تعديل نص قرار، أو اعتماد اقتراح، أو إلغاء، أو حذف نهائي، أو حذف قيد أو دفعة من السجل، أو استبدال الخلاصة. في البلقن بالأمر `/conversation-memory:fix` (يكتبها Claude مسودة)، وتمر بالكاتب نفسه: تحقق، وحذف للحساس، ونسخة احتياطية، وتراجع بزر أو أمر.
البديل المرفوض: ترك المستخدم يعدّل الملف يدوياً. السبب: التعديل اليدوي يكسر الصيغة بسهولة ولا يمكن التراجع عنه.

**20-أ. لا واجهة تصحيح في صفحة إعدادات الإضافة** (قرار المستخدم): تفاصيل لا يحتاجها مستخدم الإضافة، والتراجع عن آخر تغيير متاح من الشارة.

**21. النص المعتمد لا تُحذف نسخه أبداً.** الاسترجاع يحفظ نص النسخة القديمة نسخةً جديدة، فيبقى تاريخ التغيير كاملاً ويمكن العودة لأي نقطة. والمقارنة سطراً بسطر.

**22. النقل إلى محادثة أخرى باختيار ومعاينة، ولا إرسال تلقائي.**
المستخدم يختار الأجزاء (الخلاصة، قرارات بعينها، القيود، نصوص معتمدة، دفعات من السجل)، ويرى النص وطوله (حد 3,000 حرف) قبل أي شيء. في الإضافة يُدرج في خانة الرسالة فارغةً فقط، وفي البلقن يُكتب في ملف داخل `.conversation-memory/share/` تُشير إليه الجلسة الأخرى. والنص موسوم بأنه بيانات للمرجع، لا أوامر.
البديل المرفوض: ربط المحادثات ببعضها تلقائياً. السبب: يخلط سياقات لا يريدها المستخدم، ويستهلك دون علمه.

**23. ثلاث حالات للمؤشر لا تختلط.** ✓ حُدّث الملخص، و📝 حُفظ النص الكامل وملخصه لاحقاً، و⚠️ تعثّر. وتُعرض 📝 فقط إذا كان حفظ النص أحدث من آخر ملخص، فلا يظن المستخدم أن الملخص محدَّث وهو ليس كذلك. في الإضافة يُحفظ النص بعد كل رد، وفي البلقن يُنسخ قبل ضغط السياق وعند الإغلاق (لأن Claude Code يحفظ نص الجلسة بنفسه).

**24. الكلفة تُقاس من النص الفعلي وتُعرض تقديراً.** تُعدّ حروف الطلب الذي أُرسل للنموذج (وإعادة الطلب إن تكررت) وحروف ما كتبه (المسودة أو الرد)، ثم تُحوَّل إلى توكنات بقسمة الحروف على 3، في دالة واحدة في المكتبة المشتركة. وتُوصف دائماً بأنها تقدير، ويُذكر ما لا تشمله (ما قد يقرؤه Claude من ملف الذاكرة).
البديل المرفوض: عدّ التوكنات بالضبط. السبب: يحتاج مُرمِّز كل نموذج، ولا يتاح من داخل الصفحة أو الخطاف.

**25. التحكم بالتلخيص لكل مشروع:** تلقائي كل N رسائل، أو يدوي. في البلقن بالأمر `/conversation-memory:settings`، ويُحفظ في الحالة الخاصة للمشروع. وفي الإضافة من صفحة الإعدادات. والوضع اليدوي لا يمس الحماية من الضياع: النسخ قبل الضغط وعند الإغلاق يعمل في الوضعين.

**26. الإضافة تحفظ داخل المتصفح تلقائياً، لكل مشروع في الموقع ذاكرته** (قرار المستخدم).
مشروع في Claude أو ChatGPT ذاكرة مستقلة، والمحادثات خارج المشاريع ذاكرة لكل موقع على حدة (لا تختلط ذاكرة ChatGPT بـ Claude). لا مجلد يُختار ولا إذن يُمنح.
ربط مجلد على الجهاز اختياري، لمن يريد أن تشترك الإضافة والبلقن في ذاكرة واحدة. والربط لا ينقل ما حُفظ داخل المتصفح: يبقى كما هو ويعود إليه المستخدم بزر.
والمقايضة معلنة: حذف الإضافة يحذف تخزينها، فصفحة الإعدادات تحفظ نسخة كاملة في ملف وتستعيدها، والاستعادة لا تستبدل مشروعاً موجوداً.

**27. ملف ذاكرة لم يُكتب على هذا الجهاز لا يُحمَّل في الجلسة وحده.**
يحفظ البلقن بصمة كل نسخة كتبها، أو اعتمدها المستخدم بالأمر `/conversation-memory:trust`، في حالته الخاصة. عند بداية الجلسة يُحمَّل الملف فقط إن كانت بصمته معروفة، وإلا يخبر المستخدم بما فيه من جديد دون أن يضعه في سياق Claude.
السبب: مستودع منسوخ أو `git pull` قد يحمل ملف ذاكرة كتبه غيرك، وفيه ما يشبه التعليمات.
البديل المرفوض: تحميله مع تنبيه، لأن النموذج يكون قد قرأه.

**28. كسر قفل منتهٍ يمر بقفل كسر صغير حصري** (`<القفل>.break`).
من يرى قفلاً منتهياً يأخذ قفل الكسر أولاً، ثم يتأكد أن القفل ما زال بالمحتوى نفسه، ثم يحذفه. فلا يُحذف أبداً قفل جديد أخذه غيره في اللحظة نفسها.
البديل المرفوض: نقل القفل جانباً ثم إعادته إن تبيّن أنه حي. السبب: بين النقل والإعادة كان ثالث يستطيع أخذ القفل، فيصير له حاملان. هذا كان سبب فقد رسالة نادر في اختبار 64 رسالة متزامنة.

**29. ما يعرضه موقع المحادثة لا يصل إليه موقع المحادثة.**
شارة الإضافة داخل جذر ظل مغلق، فلا تقرأ سكربتات الموقع الذاكرة المعروضة فيها، ولا يُقبل إلا الضغط الحقيقي من المستخدم. وعامل الخلفية لا يسمح لصفحة ChatGPT إلا بذاكرة ChatGPT، ولا لصفحة Claude إلا بذاكرة Claude، ولا لأي منهما بالنسخة الكاملة.
ومشروع Claude يُعرف من رأس الصفحة فقط، لا من رابط داخل رسالة يمكن لأي أحد لصقه.

**30. بروتوكول الملفات معرّف مرة واحدة في المكتبة المشتركة** (`PROTOCOL`): أسماء الملفات، وتسمية النسخ الاحتياطية، والحدود، واسم القفل ومدة انتهائه. فلا يختلف الكاتبان في شيء يجب أن يتفقا عليه. وكذلك صيغ العدّ بالعربية (رسالة واحدة، رسالتان، 3 رسائل، 11 رسالة).

**31. أوقات النسخ الاحتياطية تُخزَّن بتوقيت UTC وتُعرض بتوقيت المستخدم.** السبب: الاسم مشترك بين كاتبين قد يختلف توقيتهما، والعرض للإنسان.

**32. البلقن يلخّص افتراضياً عند حدود الجلسة لا كل N رسائل** (1.3.0). قبل ضغط السياق وعند الإغلاق تُنسخ الرسائل التي لم تُلخَّص، ويُطلب ملخصها مرة واحدة بعد الرد التالي. السبب: Claude Code يحفظ نص الجلسة كاملاً، فالتلخيص الدوري لا يحمي شيئاً إضافياً، ويكلّف توكنز أثناء العمل. والتلخيص الدوري متاح بـ `settings every N` أو `CONV_MEMORY_MODE=auto`، والفوري بـ `/conversation-memory:save`.

**33. خروج سريع قبل تحميل أي وحدة.** `hook.js` يقرأ المدخل أولاً، وخطاف `PreToolUse` يخرج فوراً إذا لم يكن الملف داخل `.conversation-memory/`. السبب: هذا الخطاف يعمل مع كل قراءة وكتابة في الجلسة، ومعظمها لا يخصّنا. والاعتماد على سلوك خطافات Claude Code قائم ومعروف، وتختبره `npm run integration` على النسخة الحية قبل كل إصدار.

**34. الإضافة تلخّص كل 10 رسائل بطلب أقصر** (1.3.0). الطلب يحمل الهدف والوضع والقرارات السارية والقيود فقط (حد 1,800 حرف)، لا الذاكرة كاملة، وتعليماته مختصرة: نحو 640 توكن بدل 790 (ونحو 690 في 1.4.0 بعد إضافة الاقتباس ومصدر كل قرار). السبب: في المتصفح يظهر الطلب داخل المحادثة ويُحتسب من رصيد الرسائل والسياق، فكل رسالة توفَّر تُحسّ.

**35. اقتباس لكل قرار** (1.4.0؛ عُدّل في 1.5.0، انظر 40–42). كل قرار في المسودة يحمل اقتباساً حرفياً قصيراً (`quote`)، والكاتب يبحث عنه في نص المحادثة الذي عنده: سجل جلسة Claude Code أو الرسائل المنسوخة في البلقن، وما قرأته الصفحة في الإضافة. الاقتباس دائماً من كلام المستخدم نفسه: الكلمات التي قرر بها، أو موافقته على اقتراح (ولو «نعم»)، لا كلام النموذج. وأرقام القرار (عددان فأكثر) تُقارن قيماً كاملة لا أجزاء نص («500» ليست في «1500»)، وتُقبل إن كانت في المحادثة أو في قرارات سارية سبق التحقق منها أو كانت السنة الحالية؛ والقيمة نفسها بصيغة أخرى واحدة («40 ألف» = 40,000 = «40k»، واسم الشهر = رقمه). المقارنة لا تتأثر بالتشكيل والتطويل وصور الألف والياء والكاف والأرقام العربية وفواصل الآلاف وعلامات الترقيم. ما يفشل لا يُرفض: يُحفظ اقتراحاً معلَّماً (`unverified`) لا يلغي قراراً سارياً، ويُعرض للمراجعة. فإن اعتمده المستخدم صار ما ادّعاه النموذج (قرار المستخدم أو اقتراحاً معتمداً) وألغى ما كان سيحل محله، فلا يبقى قراران متعارضان. السبب: النموذج قد ينسب للمستخدم ما لم يقله، وهذا أخطر من ملخص ناقص؛ والرفض كان سيضيّع قراراً صحيحاً بصياغة مختلفة.

**36. قراءة المحادثة من بيانات الموقع احتياطاً لا أصلاً** (1.4.0). الصفحة تبقى المصدر الأول، لأن الكتابة في الخانة ومعرفة انتهاء الرد تحتاجها أصلاً. حين لا تُقرأ (بعد 4 ثوانٍ بلا رسائل، أو رسائلك بلا ردود 15 ثانية) تُطلب المحادثة من واجهة الموقع نفسه: `backend-api/conversation` في ChatGPT، و`chat_conversations` في claude.ai، ويؤخذ الفرع الظاهر وحده بلا رسائل مخفية أو أدوات أو تفكير. لا تُقارن بصمات مأخوذة من مصدر ببصمات من الآخر، لأن الصفحة والبيانات تعرضان الرد بصياغتين، فيُظن خطأً أنه أُعيد توليده.

**37. «أبلغ» وسجل التشخيص بلا محتوى** (1.4.0). التقرير يعدّ عناصر الصفحة المعروفة ولا يقرأ نصها، ويحذف من رسائل الخطأ أي نص بين علامات تنصيص قبل حفظها. السبب: البلاغ يجب أن يكفي لإصلاح العطل، دون أن يكلّف المستخدم كشف محادثاته.

**38. التلخيص بمفتاح المستخدم يمر من عامل الخلفية مباشرة إلى المزوّد** (1.4.0). المفتاح في قاعدة بيانات الإضافة الخاصة (IndexedDB في أصلها)، التي لا تصل إليها سكربتات المحتوى على مواقع المحادثة، وإذن موقع المزوّد يُطلب عند الحفظ ويُسحب عند الحذف. مهمة التلخيص لا تكتب حالة المحادثة بنفسها: تضع نتيجتها، وحلقة الصفحة وحدها تطبّقها، فلا يكتب اثنان فوق بعضهما. وإن تغيّرت المحادثة أثناء التلخيص (تعديل، أو رد أُعيد توليده) لا تتقدم الحالة عليه. والمشروع هو مشروع لحظة البدء ولو انتقلت إلى صفحة أخرى. وإن كان القفل المشترك مشغولاً تُعاد الكتابة بالرد نفسه، ولا يُعاد الطلب المدفوع.

**39. فحص أسبوعي حي على أحدث Claude Code** (1.4.0). سير عمل في GitHub كل اثنين يثبّت أحدث Claude Code ويشغّل `npm run integration`، وفشله يصل بريد صاحب المستودع. ويذكر `/conversation-memory:status` نسخة Claude Code من سجل الجلسة، وينبّه إن كانت أحدث من آخر نسخة جُرّب عليها البلقن. السبب: البلقن يعتمد على سلوك خطافات Claude Code، فالأفضل أن نعرف بالتغيير قبل المستخدم.

**40. وجود الاقتباس لا يثبت المعنى** (1.5.0). مراجعة خارجية أثبتت بالتشغيل أن «لا تنشر بياناتي» قُبل دليلاً على «وافق المستخدم على نشر بياناته». فصار الفحص يضيف ثلاثة حرّاس حتميين فوق وجود الاقتباس:
- **الاتجاه:** نفي في الاقتباس أو القرار وحده يوقف الاعتماد. يشمل «لا/لم/لن/ليس/مو» و«ما» قبل «ابي/نبي»، والإنجليزية. وتُستثنى عبارات الموافقة مثل «لا بأس» و«ما عندي مانع».
- **الاتجاه داخل الرسالة:** يُقرأ الاقتباس مع الكلمات الأربع التي تسبقه في رسالته، فاقتباس مقطوع عن نفيه («لا أريد [نشر بياناتي]») يبقى منفياً.
- **الموضوع:** يشترك الاقتباس والقرار في كلمتي مضمون، أو كلمة واحدة في القرار القصير. والمقارنة بجذر تقريبي: حذف «ال» والضمائر، ثم التطابق أو الاحتواء أو نفس الحروف الأربعة الأولى، لا مقطع في وسط الكلمة. والأسماء اللاتينية في القرار (مكتبة، منتج) يجب أن تكون كلها في الاقتباس.
- **الموافقة تتبع اقتراحها:** «نعم» تثبت اقتراحاً فقط إن كان الرد الذي سبقها مباشرة يذكر نصف كلمات مضمونه على الأقل وأسماءه اللاتينية. ورسالة موافقة فيها نفي أو تحفّظ («نعم، لكن لا تحذف…») ليست موافقة.

وكل قرار يُربط برقم رسالة المستخدم التي فيها الاقتباس (`msg`). هذه حرّاس لا برهان، لذلك فُصل «وُجد اقتباسك» عن «أكّدته» (`confirmed`)، والثانية لا تُكتب إلا بفعل المستخدم: اعتماده أو تصحيحه بنفسه.

**41. كل تغيير على ما قرره المستخدم يحتاج كلامه** (1.5.0). قبلها كان الإلغاء والقيود يمران بلا فحص. الآن:
- **إلغاء قرار للمستخدم:** يحمل اقتباساً من كلامه (`revoke: [{id, quote}]`) بشروط: يذكر القرار، ومن رسالة بعد رسالة القرار، وليس الكلام الذي قرره به، ويقول التغيير صراحة («ألغِ»، «بدّل»، «ما عاد»، «لا داعي»…). وإلا بقي القرار سارياً مع `pendingRevoke` ينتظر موافقته.
- **الاستبدال (`replaces`):** القرار الجديد مثبت بنفسه، واقتباسه من رسالة لاحقة وليس اقتباس القديم. واقتراح النموذج (`assistant`) لا يستبدل قراراً للمستخدم أبداً. ولا يدّعي القرار الجديد أنه حل محل قديم إلا إن أُلغي القديم فعلاً.
- **القيود:** إضافتها وحذفها بـ `{text, quote}`، وما لا دليل له يذهب إلى `pending.constraints` والقائمة لا تتغير.
- **اقتراحات النموذج نفسه:** يسحبها بمعرّفها بلا اقتباس.

مفاتيح المراجعة واحدة في المنتجين: `d3` و`x-d3` و`c+<بصمة>` و`c-<بصمة>`، عبر `reviewItems` و`fix.pending`.

**42. غياب الدليل يقفل الثقة لا يفتحها** (1.5.0). إذا لم يتوفر نص المحادثة للكاتب، كان كل قرار يُقبل بلا فحص. الآن كل ما يُنسب للمستخدم يُحفظ «غير متحقق»، ولا يُلغى قرار له ولا تتغير القيود.

**43. التوافق بين الإصدارات** (1.5.0). البلقن والإضافة قد يختلف إصداراهما وهما يكتبان الملف نفسه.
- **الحقول المجهولة:** `normalizeMemory` يبقيها كما هي في كل مستوى: الجذر، والقرار، والخلاصة، والسجل، والنصوص المثبتة، والمعلّق. لكل مستوى حد للحجم، والحقل الكبير وحده يُترك دون أن يُسقط ما بعده، ولا تُقبل أسماء من `Object.prototype`. فالإصدار الأقدم لا يمحو ما أضافه الأحدث.
- **الصيغة الأحدث:** ملف بصيغة أحدث (`conversation-memory/2` فما فوق) يُقرأ، لكن لا يُكتب فوقه، وتبقى المسودة ويُطلب التحديث.
- **الحقول الجديدة في 1.5 تتدهور بأمان:** لو كتب فوقها إصدار 1.4، فأسوأ ما يحدث أن يضيع «معلّق» أو «أكّدته»، لا قرار ساري.

**44. لا يُنتزع القفل من كاتب حي** (1.5.0).
- **قفل الكتابة المشترك:** صاحبه على الجهاز نفسه وعمليته حية يُحترم حتى دقيقة، لا 15 ثانية فقط. وكل حامل يجدد الوقت في القفل أثناء عمله: البلقن عند كل خطوة، والإضافة كل 5 ثوانٍ. فالكاتب الذي لا يرى العملية (الإضافة) لا يظن الكتابة البطيئة متروكة.
- **قفل الحالة الخاص:** بقي على 60 ثانية، لأن Claude Code يقتل الخطاف عند مهلته (30 ثانية بحد أقصى). فالعملية «الحية» بعد ذلك رقم أُعيد استخدامه، لا كاتب بطيء.

**45. ترحيل الثقة بإثبات** (1.5.0). عند أول تشغيل لإصدار يحفظ البصمات، يُعتمد ملف الذاكرة تلقائياً بشرطين:
- أحدث إدخال في سجله دفعة حفظها البلقن هنا (من `state.json`).
- ملف Markdown هو العرض المولَّد من هذا الـJSON نفسه (`mdHash`).

وإلا انتظر الملف `/conversation-memory:trust`. **ما بقي:** تعديل مقصود يعيد توليد الملفين معاً ولا يضيف دفعة. يكشفه هذا الفحص فقط إن لم يُولَّد العرض من جديد.

**46. مراجعة مستقلة قبل الإصدار** (1.5.0). وكيل لم يرَ العمل راجع الفرق، فوجد 13 خللاً، أربعة منها عالية:
- اقتراح النموذج يستبدل قرار المستخدم.
- الإلغاء بكلام القرار نفسه.
- الاقتباس المقطوع عن نفيه.
- الاستبدال المعاكس بكلام القرار القديم.

ومن الأقل خطورة: موافقة على أي رد طويل، وعبارات رفض لا تُقرأ رفضاً، وحقول تضيع، وتجديد قفل بعد تحريره، ومفاتيح بـ21 بتاً. كلها أُصلحت، ولكل منها اختبار يعيد المثال نفسه.
